# Audit TriBin — 25 octobre 2026

Trois volets : **A.** bugs et problèmes de logique (code), **B.** le prompt (diagnostic et nouveau skill de triage),
**C.** les fonctionnalités qui manquent pour rendre TriBin indispensable.

Méthode : carte du code construite avec graphify (2 173 nœuds, 95 communautés, `graphify-out/`), puis trois lectures
indépendantes du code (moteur et apprentissage ; service et sécurité ; interface), chaque constat vérifié dans le
fichier cité. Le prompt a été analysé à part, avec les prompts réels rejoués sur une copie de la base.

## A. Bugs et problèmes de logique

Légende : **[reproduit]** = reproduit par un vrai appel (service, Qt hors écran ou script) ; sinon établi par lecture,
ligne citée. Chemins sous `src/tribin/`. Les constats déjà corrigés aujourd'hui (menu, règles, HTML, 55 %, double
rangement…) ne sont pas repris.

### A.3 Mineurs (par zone)

**Moteur / nommage** — 44. `confidence` hors échelle : `85` → 1,0 après clamp (`proposer.py:279`) : diviser par 100 si `1 < c ≤ 100`. 45. Nom de fichier en fin de chemin ou « ~ » acceptés comme dossiers (`personal_folder("Factures/devis.pdf")` → dossier « Devis.pdf » ; `normalize_rel("~/Documents")`) (`proposer.py:74-86, 227, 250`). 46. Mode Particulier : sous-dossiers perdus sans avertissement quand le chemin ne commence pas par la catégorie ; alternatives non canonicalisées (espaces, profondeur) (`proposer.py:221-224, 300-313`). 47. `build_name` tronque au milieu d'un segment (code projet amputé) ; apostrophe typographique supprimée mais pas la droite (`naming.py:49-64, 166-174`). 48. `_Archive` et `_versions` acceptés comme destination en mode Pro (`proposer.py:254`). 49. `distinctive_words` coupe « cœur », ignore « Łódź » ; `MAX_FILES` sort en silence (`similar.py:33, 42-43, 88-89`).

**Apprentissage** — 50. `maybe_summarize` : plafond 1 000 corrections → plus jamais de synthèse ; prompt d'agence (« 06_Admin », « convention d'équipe ») même en Particulier (`signals.py:89-117`). 51. Règles confirmées sur motif générique (`facture_#.pdf` → « Les fichiers nommés comme Facture_1.pdf vont dans Logement », appliquée aux factures téléphone) (`rules_store.py:113-115`). 52. `check_moved_files` : premier fichier de même nom et taille n'importe où = « correction » ; doublon appris deux fois ; un `os.walk` par fichier manquant (`signals.py:41-55, 72-78`). 53. `team_rule_alerts` sans fenêtre temporelle : une alerte ne s'éteint jamais (`corrections.py:140-149`). 54. Statistique « sans correction » : deux définitions contradictoires (`activity.py:106-108` compte `auto` ; `journal.acceptance_rate` l'exclut).

**Extraction / convention** — 55. `extract_text` : coupure UTF-8 à 16 000 octets → tout le texte décodé en cp1252 (« Ã ») ; UTF-16 non détecté (`text.py:25-38`). 56. `redact_secrets` non appliqué aux PDF, Office, ODF, EPUB ; motif exige la clé en début de ligne (`pdf.py:32`, `office.py:40-73`, `text.py:13-15`). 57. `.heic` listé mais `pillow-heif` absent : photos iPhone « illisibles » (`image.py:12`, `pyproject.toml`). 58. Loader : pas de validation des catégories en doublon, des codes avec « / », d'un `date_format` invalide (→ chaque proposition en « erreur inattendue (ValueError) »), de `separator == word_separator` ; `_category_key` retire tout « s » final (« Bus » → « bu ») (`loader.py:21-71, 107-115`). 59. `describe_profiles` : prompt d'agence en Particulier ; description gardée par `rel` même si le contenu a changé ; `rel` renvoyé avec une autre casse non rattaché (`profiles.py:91-159`).

**Service / sécurité** — 60. `ExclusionMatcher` : motif sans `**` (dans le YAML) ne protège pas le contenu ; motifs locaux appliqués à toutes les racines (`filters.py:57-100`). 61. ### A.4 Non testé — à couvrir avant toute automatisation plus large

- **Concurrence** : aucun test multi-thread (`analyze` contre `set_aside`/`return_to_origin`/`reanalyze` ; `auto_file` contre un `commit` manuel ; deux `drop` simultanés ; journal écrit par deux threads ; `rebuild_pending_names` pendant une analyse).
- **Annulation** : inter-volumes (hash + verrou), origine occupée (`_restaure`) puis remise en file, dépôt annulé depuis l'Historique, lot dont un `mkdir` est partagé, journal tronqué puis nouvelles écritures.
- **Inter-volumes** : échec du `remove` après copie ; dépôt depuis un autre volume ; espace disque quand le dossier cible n'existe pas encore (`executor.py:176` saute le test).
- **Noms** : dossiers réservés/invalides ; > 255 octets ; casse réelle sur macOS (tests sous Windows seulement).
- **Moteur** : `personal_folder`/`new_category_for`/`user_folder` sans test unitaire ; dates (futur, formats, repli sur mtime) ; `extract_version` négatifs ; `select_candidates` (faux codes, égalités) ; `detect_client` sous-chaînes ; `similar_examples` rejets ; `find_versions` négatifs ; `light_update` évolution des compteurs ; `apply_text` sur règle confirmée ; `check_moved_files` doublons.
- **Extraction** : saturation du pool, UTF-8 tronqué, UTF-16, `.heic`, `tar.gz` volumineux, secrets dans PDF/DOCX, EPUB/ODF malformés, dates de création PDF/DOCX.
- **Interface** : petits écrans / DPI (fenêtres 1280×800, 960×660, 820×640 sans `setMinimumSize` ni clamp sur `availableGeometry()` : sur 1366×768 à 125 %, « Enregistrer » et « Ranger le fichier » peuvent passer sous la barre des tâches) ; multi-écrans ; Ctrl + Alt + T = AltGr + T sur certaines dispositions.
- **Performance** : journal de 50 000 lignes ; racine de 100 000 dossiers (`folder_signature` et `PlacedFiles` parcourent tout).

## B. Le prompt

Diagnostic détaillé, architecture et texte complet du nouveau skill : [triage-skill-v2.md](triage-skill-v2.md).

En résumé, le prompt actuel (p7 / p8-perso) est une liste de règles accumulées essai après essai. Il lui manque :

1. **une méthode** : observer (contenu → nom → type → origine), situer (règle › modèle de nom › série › dossier du
   même sujet › catégorie par nature), décider, nommer, évaluer ;
2. **la distinction nature / thème** (des logos ne sont pas des photos ; une facture d'un projet reste une facture) ;
3. **deux prompts complets** au lieu d'un prompt d'équipe rafistolé pour le mode Particulier ;
4. **un barème de confiance ancré** sur des faits observables, et **trois exemples** ;
5. **l'analyse avant la décision** (quatre champs en tête du JSON : nature, sujet, source de la date, indices) ;
6. **une vraie date de document** (jamais la date du fichier) ;
7. **un outil `lister_dossiers`** que l'IA appelle pour lire l'arborescence quand elle en a besoin (vérifier qu'un
   dossier existe avant d'en créer un, voir les sous-dossiers d'une catégorie), au lieu d'une arborescence collée dans
   chaque prompt ;
8. **un préfixe stable mis en cache** (consignes + convention + profil + règles dans le `system`) : ~70 % des tokens
   d'entrée en moins sur un lot.

Plan de mesure : jeu d'essai Particulier à créer, `tribin eval` p7 contre v2 sur les deux jeux, critère de bascule
« au moins autant de dossiers acceptables, moins d'erreurs à plus de 0,8 de confiance ».

## C. Ce qui manque pour devenir indispensable

Aujourd'hui, TriBin est un bon outil **quand on pense à s'en servir** : il faut glisser un fichier, ouvrir la fenêtre,
valider. L'indispensable, c'est l'outil qui travaille **sans qu'on y pense** et qui **rend quelque chose qu'on n'avait
pas** : du temps, de la mémoire, de la tranquillité. Classement par ce qu'un utilisateur ressent au bout de deux
jours, puis par effort.

### Jour 1 — « Il a tout rangé pendant que je faisais autre chose »

| # | Fonctionnalité | Pourquoi ça rend indispensable | Effort |
|---|---|---|---|
| 1 | **Surveillance des Téléchargements** (et du Bureau, des Captures d'écran, au choix). Tout fichier qui y arrive est analysé ; au-dessus du seuil il est rangé, sinon une notification propose « Ranger · Voir · Pas celui-là ». Délai de grâce (fichier encore ouvert ou en cours d'écriture), exclusions (.exe, .msi, .torrent, fichiers partiels), bouton « Pause 1 h ». | C'est le passage de « je dois y penser » à « ça se range tout seul ». Le soir du premier jour, Téléchargements est vide. Tout le reste de l'appli existe déjà pour ça (seuil, simulation, annulation). | 2–3 j (QFileSystemWatcher + file d'attente existante) |
| 2 | **Démarrage avec Windows** + mode discret (icône seule, fenêtre fermée). | Sans ça, l'outil n'est pas là quand le fichier arrive. Une case dans Réglages › Système. | 0,5 j |
| 3 | **Grand ménage d'un dossier existant** (« Ranger ce dossier ») : TriBin analyse par lots de 20, groupe les propositions par destination (« 34 fichiers → Factures, 12 → Etudes/CV… »), on valide par groupe, on dégroupe ce qu'on veut voir. Reprise possible. | Le résultat visible dès la première heure. C'est aussi la promesse déjà faite dans l'onboarding (« À réorganiser — bientôt disponible »). | 3–4 j (nouvelle vue par lots ; moteur existant) |

Hash SHA-256 déjà disponible (`safety/hashing.py`). | Téléchargements est le royaume des « fichier (1).pdf ». Supprimer un doublon en confiance est un vrai soulagement. | 1–2 j |

| # | Fonctionnalité | Pourquoi | Effort |

| 13 | **Export ciblé** : « tous mes documents Impots 2026 » → dossier ou zip, avec un sommaire. | Le jour de la déclaration ou d'un dossier de prêt, c'est ce qu'on cherche. | 1 j |

### Ce qu'il ne faut pas faire tout de suite

- Un chat « demande à TriBin » : la recherche (5) couvre 90 % du besoin pour 10 % de l'effort.
- Le multi-appareils / compte en ligne : la base locale suffit ; OneDrive synchronise déjà les dossiers.
- Plus de fournisseurs d'IA : la qualité vient du prompt et du contexte, pas du modèle.

### Ordre conseillé

1 → 2 → 8 → 7 (une semaine : l'appli devient ambiante et sûre), puis 5 → 3 → 4 (la mémoire et le ménage), puis 6.
Avant tout cela : le skill v2 et sa mesure, parce que chaque fonction ci-dessus multiplie le nombre de propositions
que l'utilisateur ne relira pas.
